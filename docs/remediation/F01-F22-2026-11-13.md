## Single-command cPanel publication helper (14 November 2026)

The source repository includes a pinned, fail-closed production operator:
\`scripts/cpanel_finalize_release.sh\` and CLI-only private helper \`scripts/cpanel_finalize_db.php\`. This operator is **not** the live deployment; it must be executed by the authorized cPanel account owner.

Run a pinned operator commit with \`--check\` (read-only readiness) or \`--publish\` (explicit authorization to apply a backup-gated upgrade). The script fetches the operator scripts from that immutable commit and deploys only application commit \`e032577d94860ef3336499e770f439f231c886de\`, which contains the merged authenticated-navigation, verified sender-envelope and F01 HEAD corrections.

The \`--publish\` workflow:
1. Check all six sensitive GET and HEAD paths on both hosts over HTTP/1.1. Inconclusive or non-denied response is a hard stop.
2. Prepare/reuse an isolated private migration stage outside \`public_html\`, confirm exact release and unchanged live app configuration.
3. Read-only scan for provider reference duplicates and stop for human reconciliation rather than modifying financial records.
4. Export full InnoDB-consistent SQL (including triggers, events, routines), verify gzip and required tables, encrypt under a key stored separately in \`$HOME/iworks-release-keys\` with 0700/0600 protection, and retain SHA-256 manifest under \`$HOME/iworks-release-operations\`. The encryption passphrase is **not printed**. The key must be retained separately for any disaster recovery; a server compromise could expose both.
5. Require a real full SQL restore into a newly created, uniquely named rehearsal database, compare critical entity row counts, then remove **only** that rehearsal database. The script creates, grants privileges for, and deletes the **new rehearsal database via cPanel UAPI**, preserving the hosting account’s MySQL database mapping. If cPanel UAPI, database capacity, privileges or actual SQL restoration are unavailable, it stops with the encrypted backup intact and without applying migrations. Do not replace cPanel UAPI with raw MySQL `CREATE DATABASE` or `DROP DATABASE`, and do not remove this gate.
6. Apply controlled idempotent schema migrations after verified backup, invalidate outstanding exposed OTP/reset tokens, send a controlled mail-transport test and enable the configured notification transport only if the send is accepted. PHP \`mail()\` acceptance is *not proof of inbox delivery*. 7. Run mandatory read-only schema/mail/private-file preflight and then the pinned source installer \`--apply\` (which backs up replaced application files and restores them if copying fails). Run final public HTTP 200, private HTTP-denial and signed-in navigation source checks.

**Never claim complete acceptance from a successful script alone.** Payment provider sandbox callbacks/amounts/signatures, real account sign-in/OTP/reset and outbox delivery, cron workers, browser responsive/accessibility, database reconciliation and the audit ledger's outstanding checks must still be tested. Codes now have a minimum 10-minute and maximum 20-minute validity window; any prior 1-minute admin value is effectively clamped. Delivered queue rows scrub raw OTP/email body. The original five-wrong-code lockout and persistent throttles remain.
