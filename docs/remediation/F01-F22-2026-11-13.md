## Release prerequisites and order (do not bypass)

1. **Immediately contain F01** on both document roots using \`scripts/contain_private_http_access.sh\` from the merged repository, with \`--check\` and then \`--apply\`. It creates private evidence, preserves existing rewrite rules, adds deny rules, quarantines old logs and checks safe GET/HEAD status without downloading content. Confirm the checks independently. Preserve incident logs privately. Do not send private messages/tokens into chats.
2. Establish an **encrypted, verified private database backup** and a staging restore/rollback rehearsal, plus a backup of both document roots. Do not run migrations first.
3. Review duplicate gateway transactions and provider settings; set legitimate mail sender and test transport on a controlled account. Check any external OTP/rate scheduler. Determine CAC tax policy; preserve 0% existing baseline until approved.
4. Run standalone read-only \`scripts/check_remediation_release.php\` from the proposed immutable source. Missing schema, private HTTP denial or mail configuration is a **hard stop**.
5. Prepare an isolated private migration stage outside `public_html` with the immutable release using `scripts/prepare_private_migration_stage.sh --prepare PORTAL_ROOT COMMIT_SHA`. The helper copies private `app/config.php` with mode 0600 and performs no database mutations. From the stage, inspect each `--check` and, **only after verified SQL backup and staged restore**, run separately with `--apply --backup-confirmed`: `scripts/migrate_legacy_schema.php`, `scripts/migrate_gateway_uniqueness.php`, `scripts/migrate_auth_attempt_limits.php`, `scripts/migrate_notification_email_outbox.php`. Read-only checks must never execute DDL; confirm migrated schema with the release preflight.
6. Verify real mailbox OTP/reset/branded ticket follow-ups and paystack/flutterwave/stripe **sandbox** amounts/signatures/duplicated callbacks; test rate-limit recovery and customer sign-in. Test role-specific documents with synthetic accounts.
7. Pin installer to verified immutable feature SHA. Run installer \`--check\`; it runs the same read-only preflight and reports missing schema, mail and private-file protections without changing site files. Both \`--check\` and \`--apply\` must **fail closed before copying files** unless release preflight passes. Do not deploy an unaudited override. Ensure approved SVG/Insights/blog files are all in the same archive.
8. If all checks pass, \`--apply\`, compare source hashes on both live paths, inspect Apache GET/HEAD denial of sensitive paths, image MIME, new product page HTML, payments, sign-in and responsive widths. Monitor private logs/health. On failure restore the private backups; revert source only after assessing compatible schema. Never blindly rollback customer financial records.
9. Configure cPanel Cron Jobs only after checking external schedulers; use \`scripts/install_scheduled_jobs.sh --check\`, then confirmed \`--apply\`. Verify processed/failed/age metrics, upstream rate age, and notifications to test addresses.
